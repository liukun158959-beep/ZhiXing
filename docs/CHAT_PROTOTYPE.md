# tebb 协作聊天原型

2026-10-15：先完成聊天交互，云架构在聊天功能实现后再确定。首版对象为「一个真人＋多个 Agent」。

本次交付是本地可操作原型，不调用模型、联网搜索、终端或飞书，不代表真实多 Agent 后端已经实现。原有真实聊天仍可使用。

## 打开与评审

在 `client` 目录运行 `pnpm dev`，打开：

`http://localhost:5180/client.html?preview=chat`

这个独立入口不挂载原客户端 App，不连接 Python 后端，也不读取真实聊天、模型配置或凭据。开发客户端侧栏另有「协作聊天 · 原型」入口，深浅皮肤跟随客户端；独立预览可自行切换主题。

推荐体验顺序：

1. 查看「AI 研究室」的初始委派。默认暂停，点「推进一步」观察研究员完成、成果交接、写作者接续；也可开启/暂停自动演示。
2. 任务执行中直接发消息，聊天立即响应。选择「交给 Agent」创建另一项后台演示任务；不同独立任务同步推进。
3. 点任务卡的「补充要求」，输入「优先比较部署成本」。提交后先显示已接收，下一步显示已应用；补充只作用于所选任务。
4. 停止研究任务，依赖它的写作任务同步停止，其他独立任务继续。
5. 切换 Agent 私聊，草稿与群聊分别保留。通过「发送给」或消息开头的 `@研究员 ` 指定当前群的成员。
6. 打开成果文档样例，点「演示交付确认」，在待办中确认或拒绝；这些操作不会真的向飞书发送内容。
7. 新建协作群，选择至少两个 Agent；创建 Agent，修改职责、模型标记、工具勾选及私有演示记忆。

原型数据保存在独立 localStorage 键 `tebb.chat-prototype.v1` 中，不是生产记忆隔离方案。不要填写密钥或隐私资料。退出或刷新会保留演示消息、配置与任务；草稿和自动播放开关不持久化。重新打开默认暂停，不暗中推进。存储失败会提示，可继续操作；结构损坏时回到初始场景。

「重置演示」需再次确认，仅删除此原型的数据，不修改真实聊天、记忆或设置。

## 已落实的交互与边界

- 独立 Agent 私聊与有共同目标的协作群。
- 可编辑 Agent 模板；群协调者显式委派，最多两位执行者依次演示交接。
- 消息与任务两种明确发送方式，后台任务不锁住输入。
- 每个任务独立记录状态、补充、依赖与成果，停止级联到依赖任务。
- 成果文档、执行记录、跨会话待办，以及只记录一次的交付决定。
- 消息为文本显示，不将用户输入作为 HTML 执行。
- 深浅主题与窄屏会话菜单、可收起详情；弹窗支持 Esc、焦点循环及关闭后返回焦点；中文输入法组合中回车不发送。

## 真实聊天接线的下一步

先确定原型交互，再逐步接真实本地执行，保持云架构未定：

1. 建立独立 Agent、Conversation、Message、Run 数据模型，迁移旧会话前备份；用户输入、群消息顺序与任务执行上下文分别存储。
2. 将 reducer 的演示动作替换为真实消息提交和任务事件订阅，处理重连游标、消息去重、运行中补充与实际停止回执。
3. 按 Agent 配置真实模型、Skills 与工具白名单；服务端校验权限，区分用户共享/Agent 私有/群共享记忆。
4. 用真实研究→写作闭环验证委派、依赖、失败、取消与恢复；交付确认沿用已授权范围，外部写入核实回执后再补发。

参考资料：[Manus Cue 官方介绍](https://manus.im/zh-cn/blog/introducing-manus-2-0)、[Agent 与子任务 API](https://open.manus.ai/docs/v2/agents-overview)。本原型的发送方式、协调规则和任务状态是 tebb 的设计选择，不宣称复刻 Cue 内部实现。
