# 将 tebb Agent 接入飞书应用

飞书 CLI 提供机器人事件监听、消息回复、API schema 和嵌入的开发技能；应用配置、权限、事件订阅及发布流程见飞书官方开发文档。tebb 使用 CLI 管理凭证与长连接，不复制 App Secret 或用户 Token。

## 官方文档

- [飞书开放平台文档总索引](https://open.feishu.cn/llms.txt)
- [企业自建应用开发流程](https://open.feishu.cn/document/develop-process/self-built-application-development-process)
- [机器人概述](https://open.feishu.cn/document/client-docs/bot-v3/bot-overview)
- [使用长连接接收事件](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)
- [接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)
- [回复消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/reply)

长连接适用于企业自建应用。机器需要能够访问飞书公网服务，接收事件不需要公网 IP、域名或内网穿透；tebb 关闭或电脑离线时无法回复。当前接入仅接受绑定用户的私聊，不处理群聊或其他用户的消息。

## 配置应用

1. 复用 `lark-cli whoami` 显示的应用，在飞书开发者后台开启机器人能力。
2. **权限管理**：添加 `im:message.p2p_msg:readonly`（读取发给机器人的单聊消息）；回复开通 `im:message:send_as_bot`。官方回复接口也允许 `im:message` 或历史权限 `im:message:send`，开通一项即可。
3. **事件与回调 → 事件配置**：订阅方式选择「使用长连接接收」，添加 `im.message.receive_v1`（接收消息）。开启权限不等于完成事件订阅。
4. 创建版本、设置应用可用范围并发布；需要管理员审批的权限和版本须审批通过。确认本人能够在飞书搜索并私聊机器人。
5. 本机安装 Node 与 `lark-cli`，配置该应用，登录本人账户。已有配置和登录可直接复用；机器人收发使用应用身份，个人日程、待办等工具继续使用现有用户授权。
6. tebb 主窗口 **飞书 → 在飞书使用 tebb Agent → 长连接设置**，选择已配置的应用并保存，再点击「接入飞书」。界面显示绑定应用、允许私聊的用户和连接状态。等待「已接入」后再发消息。

开启后默认在重启 tebb 时恢复连接；「停止接入」关闭当前消费者并取消启用状态。首次绑定保存所选应用 profile、App ID 和登录用户 open_id；应用或用户变化时拒绝自动换绑。

## 可视化长连接设置

在飞书页面可以修改：

- **飞书应用**：选择 CLI 已配置的 profile，可刷新应用列表；此处选择不切换 CLI 默认应用，个人工具继续沿用原来的默认身份。
- **tebb 启动时自动接入**：关闭后仅手动接入；还需接入处于启用状态才能在下次启动恢复。
- **网络断开后自动重连**：适用于临时网络故障；初始间隔默认 2 秒，指数退避至最大 30 秒，两项均可设为 1～300 秒。权限错误、无效密钥和连接占用需修复后手动接入。
- **重新绑定登录用户**：勾选后保存，会清除旧私聊绑定，下次接入验证所选应用的登录用户。切换 profile 也会清除旧绑定。
- **更新 App Secret**：先停止接入，在密码框填写重置后的密钥并点击「更新应用密钥」。使用 CLI stdin 更新同名 profile，保留其他应用及原有用户登录；兼容无名 profile 时将名字设为其原有选择器，默认身份不变。tebb 配置、界面状态和日志不保存或回显密钥，提交后清空密码框。
- **检查连接占用**：按所选应用查询平台在线连接数与本机 CLI bus 状态，并显示检查时间。密钥无效时会提示先更新；在线数为零表示可尝试接入，最终以「已接入」为准。
- **打开所选应用后台**：修改机器人能力、平台事件订阅及权限并发布。接收事件 `im.message.receive_v1`、仅接受本人私聊及 CLI 管理心跳在界面展示为说明。

设置需先停止接入再修改，保存后重新接入生效。连接占用检查不会停止其他服务，也不会向飞书发测试消息。

在继承 Hermes / OpenClaw 环境的 tebb 进程中，更新密钥会针对已存在的同名、同 App ID profile 使用 CLI 的 `--force-init`，避免初始化保护误拦截凭证更新；此操作不会新建飞书应用或更换个人工具身份。

若接入提示「App Secret 无效」，应在 tebb 的长连接设置中更新所选应用密钥，再检查连接；用户重新登录不能修复机器人凭证。若终端校验成功而 tebb 仍失败，以 tebb 里的检查结果为准，核对其启动环境和凭证存储访问，必要时正常退出并重启。CLI 的 `auth status --verify` 即使退出码为零，也可能报告机器人 `available: false`、`verified: false`，不能只凭命令成功判断已认证。

## 在飞书使用

| 输入 | 行为 |
| --- | --- |
| 普通文字或富文本 | 调用 tebb 当前模型和 Agent，可使用已配置的日程、待办、GitHub、搜索、记忆、MAA 等工具 |
| `/help` | 查看指令 |
| `/status` | 查看机器人接入状态 |
| `/new` | 新建飞书会话，保留旧历史 |
| `/skills` | 查看技能列表 |
| `/skill 技能名 问题` | 注入该技能正文执行这一轮 |
| `/kb 问题` | 调用 tebb 知识库；需要已准备的知识库和模型 |
| `/mcps` | 查看本机已配置的 MCP 工具 |
| `/mcp 服务器名/工具名 问题` | 挂载并使用指定 MCP 工具 |

例：`今天有哪些日程和未完成待办？`、`查询 ZhiXing 仓库最近的变更`。不要把示例技能名或 MCP 名当成已经安装的实际名称。

模型回复完成后以机器人身份回复原消息，长回答分段发送。当前不是流式卡片，不支持图片、文件、音视频问答；这些消息会收到文字提问提示。每个问题最多 16000 字。飞书会话与桌面当前会话分开保存，桌面和飞书共用 Agent 时串行执行；桌面操作会等待当前任务完成。

这相当于从飞书操作本机助手，绑定用户可以调用 tebb 原有工具。模型接口、工具、技能及个人服务的权限仍以本机配置为准。当前消息采样固定为 low、temperature 0.5、top_p 1；不会把思考过程或异常堆栈发送到飞书。

## 长连接被占用

同一应用存在多个长连接时，飞书会在连接之间分配事件，不能保证每条消息到达 tebb。CLI 因此会在检测到其他服务连接时拒绝启动；tebb 保留这项检查。

`lark-cli event status --json`、`lark-cli event stop --app-id 应用ID` **只检查和停止本机 CLI bus**。本机没有 bus 而平台仍有在线连接时，须停止原设备/服务的监听进程，等平台连接超时清除，或改用另一个应用。CLI 没有远程踢掉未知连接的功能，见 [官方修复说明](https://github.com/larksuite/cli/pull/1454)。给 bot 执行用户登录无法解决连接占用或 bot 缺少 scope。

## 数据和恢复

`feishu_agent.json` 保存启用状态、所选应用、自动接入、自动重连、重连间隔和绑定身份，不含凭证。`memory/feishu_agent.sqlite3` 保存消息去重、飞书会话映射及待回复内容；聊天仍使用现有聊天历史。两者都属于本机用户数据，不进入仓库或公开包。

事件消费者快速持久化消息，再由工作线程调用 Agent。消息以 App ID + message_id 去重，避免重推触发重复工具调用；event_id 只标识投递，不作为去重键。排队超过十分钟的请求不再执行。已生成的答案发送失败会重试发送，不重新运行 Agent；超过回复去重窗口或重试次数后保留失败记录。处理中断时不重跑可能已执行的工具，会提示本人先核对原任务结果。

身份校验和 CLI 监听的临时网络/服务故障都按保存的间隔退避重连，启动时首次失败也会恢复；取消接入可停止等待。每次身份恢复都重新核对同一应用、profile 和绑定用户，身份变化不会自动换绑。明确的密钥、权限、配置或连接占用错误显示在界面，修复后点击「重新接入」，不建议用重新登录来处理网络故障。

飞书页的「连接诊断」保留最近30条本次运行的身份校验、连接、失败、重试和停止记录，并显示下次重试时间；日志只写错误类别与重试间隔，不记录凭证或原始 CLI 错误。平台连接检查只把所选应用的本机 bus 计为运行，其他应用的连接不会冒充它。

没有出现 CLI 的 ready 标记时，不显示已接入；ready 证明消费者已开始监听，不能保证此后网络永不中断，收到运行错误或进程退出会撤销接入状态并按原因恢复。

客户端正常退出时先通知本地助手，关闭自有事件消费者的 stdin，等待 CLI 按协议退出；不会直接停止其他消费者共用的 bus。重启客户端前应正常退出旧实例。

## 验证范围

离线测试覆盖真实 tebb Agent 的工具调用循环、消息过滤与去重、历史隔离、桌面与飞书并发、分段回复恢复、CLI 子进程 ready/NDJSON/stdin 关闭协议和界面启停。实际应用仍需在解除连接占用、配置好事件与权限后，在飞书私聊发一条消息完成收发验收。
