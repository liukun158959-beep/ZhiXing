# 聊天输入与执行过程回归（2026-10-17 / #108）

## 修复原因与行为

- 桌宠流程气泡是独立 HTML，没有主窗口的滚动条样式。现在使用透明轨道、低对比深色滑块，并为 WebView 的原生滚动条指定深色外观。
- 主聊天和浮动聊天输入框此前只有固定高度及手动拉伸。现在随输入、粘贴、草稿恢复、窗口宽度变化自动增高，清空后收缩；主窗口最多 240px / 32vh，浮窗最多 160px / 30vh，超过上限内部滚动。
- 普通模式原本隐藏执行记录。现在每条伙伴消息旁显示真实思考状态、调用工具及可展开的记录；内部推理原文仍不进入聊天或持久记录。
- 路由阶段原本隐藏所有增量，普通回答也要等完整响应返回。现在直接回答逐段展示，路由 JSON 继续隐藏。转入后台任务后不再插入固定的“已开始处理”回复；历史交接消息也由展示层折叠，记录不删除。
- 综合报告在 `submit_deliverable.report` 工具参数中，原本整份返回后才展示。现在只解码报告字段的完整字符串前缀，支持跨片段转义与 Unicode；其余控制参数不展示。正文作为生成中内容出现，最终仍经过原有交付、来源检查；修订会清除旧草稿。
- 主聊与浮窗每 400ms 检查变化；同步使用有限缓存与增量补丁，未命中则获取完整快照。前端拒绝过期补丁，切换会话与操作回包不会被旧轮询覆盖。旧后端暂未重启时可回退到原同步协议。
- 流式更新跟随底部；用户上滚阅读时保持当前位置。
