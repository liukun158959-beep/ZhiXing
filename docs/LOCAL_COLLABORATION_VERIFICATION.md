时间：2026-10-15 夜至 2026-10-16，Asia/Shanghai。不是纯模拟测试；以下在线场景均调用了本机已有模型配置。

## 已通过的真实执行场景

| 场景 | 实际观察 |
| --- | --- |
| 给定材料的研究→写作 | 协调者生成计划，研究员比较三个虚构框架，写作者得到研究成果并输出报告，正确选择满足内存与插件条件的框架丙，包含验收标记。这里验证模型执行与交接，不把虚构材料当作现实项目事实。 |
| 追加要求 | 研究任务收到“指出甲缺插件、乙超内存”的补充，应用版本为1，最终报告保留该约束。调用过程中收到补充、迟到补充不提前交接另有确定性回归覆盖。 |
| 聊天与任务分离 | 首轮长任务进行时，另一条聊天消息独立完成；重复提交相同消息编号只产生一个聊天工作。 |
| 真正停止进程 | 另一条协作链中研究员已经进入模型调用后，停止根协作链，研究任务转为 cancelled，等待中的写作者取消且模型调用次数为0。 |
| 浏览器权限 | 使用实际临时能力凭证连接 `/collaboration` 成功；同一连接调用 `terminal_start` 被拒绝。 |

第一轮给定材料场景共4次真实模型调用（计划、聊天、研究、写作各1次），模型回传用量合计输入2170、输出869 tokens。这不是模型性能基准，也不包含其他验证场景。

## 联网场景没有完整通过

1. 首次开源项目研究的搜索失败，研究任务失败，写作者没有启动。
2. 后续一次查询取得 AutoGen 官方来源，研究与写作交接完成，但缺少 LangGraph 来源；报告明确列出信息缺口与“仅搜索摘要、未读全文”的限制。该轮并行聊天曾达到90秒等待时限；没有阻止长任务继续完成。
3. 以简短官方查询词复跑时，两次搜索均超时，任务保留 `RetryableSearchError` 诊断，写作者取消。没有将这轮标记为完整通过。
4. 独立终端探针曾成功取得 LangGraph 官方文档/GitHub 搜索摘要；核对后端与终端的代理及证书环境，没有发现这些环境变量的差异。尚不能将问题归因于本地代理配置，也不能宣称搜索稳定性已解决。

为继续观察聊天响应，协调者单独选用了已有 `glm-5.3-flash` 模型（全局激活模型不变），随后聊天成功，但耗时约59秒。研究和写作仍沿用原模型。模型响应延迟是当前待优化项，不因队列分离而自动消失。
