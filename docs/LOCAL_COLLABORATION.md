# 本地真实协作验证

此功能在 main 分支验证，尚未打包到公开 v0.2.3。云架构仍未确定；关闭本地后端不会继续执行。

## 入口与范围

开发客户端侧栏 → **协作聊天 · 真实验证**。

交互演示仍在 `/client.html?preview=chat`，与真实数据分开。真实页面使用 `/client.html?preview=chat&live=1`，需要本地认证连接；普通浏览器不能匿名调用完整后端。

首版支持一个真人与多个 Agent：私聊、协作群、成员配置、独立模型条目、手动维护的私有记忆、消息、后台任务、实际成果及执行记录。模型使用设置页已配置的 API，不把密钥发回页面。

本轮工具仅开放 `web_search`。模型不能执行终端命令、读取任意本机文件、写飞书或其他外部系统。工具权限由后端检查，不能通过改提示词或浏览器字段绕过。

## 使用

1. 在成员中为协调者、研究员和写作者选择已有模型；留空沿用提交时的激活模型。设置变更不改动已提交任务的配置快照。
2. 使用「发消息」直接聊天；选择「交给 Agent」创建长任务。`@成员名 ` 或发送对象下拉框指定当前群成员；默认由协调者响应。
3. 群协调者真实调用模型生成计划。计划必须只涉及群内执行者，最多两项、不重复成员、依赖只能指向前序任务。校验失败不派发；最多一次格式校正。
4. 后台长任务和聊天分别排队。最多两项长工作与一条聊天同时执行；模型服务慢时聊天本身仍可能等待或超时。
5. 「补充要求」绑定任务编号；接收与应用分别显示。若生成答案过程中收到补充，旧稿不能先交接。在调用预算内重新整理，预算不足则保留部分内容并明确失败。
6. 停止单任务会停止依赖它的后续任务；完成委派后也能「停止整条协作链」。停止会终止实际工作进程，保留已生成内容，不承诺撤销已完成操作。

## 防止相互干扰

- 只有明确的用户提交创建工作，Agent 消息不自动触发其他 Agent，执行者没有委派工具。
- 不同任务使用独立上下文和进程。模型只收到当前会话的公开历史、群目标及该 Agent 的私有配置；不注入旧桌宠的全局事实文件或其他 Agent 的私有记忆。
- 计划深度固定一层；每项工作累计最多6次模型调用、2次搜索、3次用户补充。单次执行总时限5分钟；同一工作修订时保留累计调用预算。
- 消息提交使用去重编号；相同编号重试返回现有状态，编号被改成另一项操作时拒绝。任务队列使用稳定编号，覆盖提交成功而状态事务未提交的恢复窗口。
- 子任务只在前序成功且最新补充已应用后启动。失败、取消、超时、重启中断均不会被当作成功成果继续交接。
- 研究交接同时携带实际工具返回的资料与研究正文，写作者可核对来源；搜索仅提供标题、摘要、URL，不代表已读取网页全文。
- 搜索失败可以在剩余预算中调整关键词；所有搜索均失败时不交付无依据报告。部分来源缺失时报告仍可能只完成有依据的部分，应查看信息缺口，不能把「模型完成输出」等同于目标已全部满足。

## 数据与浏览器验证

真实数据在 `memory/collaboration/workspace.sqlite3`；长任务、聊天各有独立队列数据库。失败和取消的部分答案不写入原桌宠聊天历史。原型 localStorage 数据不导入真实上下文。

若需要在浏览器实测，启动本仓库客户端及 Vite 后运行：

```powershell
python scripts/preview_collaboration.py --open
```

这会显式打开系统浏览器。省略 `--open` 时只生成本地 `memory/collaboration/preview-launch.json` 并输出文件位置，可由 Codex 打开其中的 URL。链接中是两小时有效、仅协作接口可用的临时能力凭证，不能调用终端或普通聊天接口；完整后端 Token 不交给浏览器。支持的 Origin 为本机 Vite 的 localhost/127.0.0.1:5180。

页面读取链接后移除地址中的凭证，仅保留在当前标签页的 sessionStorage。后端端口变更或凭证过期后重新生成入口。生成新入口会撤销之前的浏览器能力凭证。桌面客户端通过原有认证接口连接，不受该临时入口限制。

## 当前限制

- 这是本地实验功能，不含云端常驻、多真人权限、自动记忆提炼或外部交付审批执行。
- 任务和消息重连通过状态版本与轮询恢复；UI 关闭不取消后端任务，后端重启则保留中断状态，不盲目重跑。
- 不会自动把失败任务无限重试。模型响应延迟、搜索网络失败、过时过滤词导致来源不足都可能发生，需结合时间线和真实回执判断。
- Agent 记忆作用域是本地单用户的上下文隔离，不是多租户安全实现；勿保存密钥。
- 回归覆盖确定性任务调度、权限、取消、补充与去重；模型输出质量仍需通过实际任务持续评估。
