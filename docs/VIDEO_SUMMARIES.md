# 视频信息与字幕总结

## 使用

左侧「看板 → 视频读取」新增独立页面。粘贴链接，点击「读取并分析」，即可查看真实任务进度、结果、字幕状态和章节，在所选记录中继续追问或保存到飞书。每个新链接使用独立会话；切换页面、断开页面连接不会停止后台任务，重新打开页面可查看结果。读取记录也包含之前在桌面对话和飞书中实际调用过视频工具的任务；普通聊天不会因为同会话读过视频而混入列表。

在 tebb 桌面对话或飞书机器人私聊发送一个 Bilibili / YouTube 视频链接，例如「总结这个视频：链接」。仅发送链接也会按视频总结处理。支持 YouTube watch、youtu.be、shorts、live、embed，Bilibili BV/av、分 P（`?p=2`）与 b23.tv 分享链接。当前不处理播放列表、频道、番剧和批量下载。

有平台字幕时，默认生成主题明确、简洁易懂的中文学习笔记，通常约 800–1500 个中文字符（不含 URL），按内容复杂度调整。概念科普重点讲清术语含义、解决的问题和相互关系；操作教程重点整理步骤与原理；观点讨论再展开论点与依据。只补充理解主题所必需的关联知识，用一个短例子串联，不默认生成长篇作者评析、失败诊断或选型报告。关键出处保留少量字幕时间链接；英文标题附中文译名。可继续追问展开某个概念，首次读取后的来源保存在本机会话目录供核对。

作者观点、补充知识和模型分析就近简洁区分。涉及当前协议/框架/产品能力、主流技术现状或影响理解的争议时，读完字幕后复用 `web_search` 核实最关键的 1–2 个问题，技术证据只接受官方资料、原始论文或官方仓库。搜索只返回标题、摘要和链接，不能把它当作已读全文或视频内容；失败时标注核实缺口。用户要求不联网时遵从。所有入口共用 `VIDEO_CONTRACT`，视频页也按主题与学习目标组织内容。

包含其它操作的普通 Agent 任务调用视频工具时，仍使用 `VideoContextCompactManager`：本轮实际调用视频工具后，上下文不超过 64,000 token 时保留已读字幕及检索结果，避免 Atlas 默认 8,000 token 通用压缩把较早的字幕工具结果截成 200 字，或生成不适合内容分析的任务进度摘要。下一轮普通聊天恢复原有压缩。超过保留预算仍走通用压缩，并向模型注明已读证据受到压缩，不能声称全面分析。独立视频笔记使用下文的分段流程，不依赖把全部字幕放入一次模型调用。这不是对任意长度视频的完整理解保证，也不改变模型服务自身的上下文上限。

这次改动调整分析目标、证据归属、上下文保留和输出要求，未增加独立模型审核阶段。模型可能未完全遵守要求，自动化工具测试也不能证明语义质量；需要用真实字幕和当前模型抽查下面的标准。

## 内容质量验收

### 字幕读取与失败恢复

B站只请求视频元数据与带 WBI 签名的字幕接口，不获取播放格式。字幕和平台章节从同一次接口响应读取，减少重复请求。验证接口业务状态码：限流／平台拒绝、需要登录、网络失败、响应格式异常与确认无字幕分别处理；接口错误不能当成视频没有字幕。记录安全的诊断字段（阶段、状态码、错误类型、轨道数），不记录 Cookie 或字幕下载地址。

完整字幕在所属会话下另存 `video_sources/<session hash>/complete/<source id>.json`。刷新失败、取得空字幕或不完整字幕时保留已有完整来源及文档回执；使用此前字幕时明确提示来源时间和本次刷新失败原因，不冒充实时读取，不跨会话复用。成功缓存七天；无字幕／登录要求缓存五分钟，接口失败缓存三十秒，显式刷新不等待缓存过期。无可用字幕的分析任务标记失败，给出具体原因，不显示「任务已完成」，不生成空笔记或自动归档。

- 用简短概览说明概念所处层次、如何配合；技术、协议、框架、产品分别定位，不照搬成必然演进路线。

## 网络与登录设置

左侧「视频读取 → 视频读取设置」：

平台登录入口位于独立视频页的「平台登录与视频浏览」。点击 Bilibili 或 YouTube 的「登录 / 扫码」，进入平台官方账号页（Bilibili 使用 `passport.bilibili.com/login`），在官方页面自行扫码或登录，保持窗口打开，回到 tebb 点击「使用此登录态」。再点击「查看视频」打开输入链接；无对应链接时打开平台首页。各平台使用独立的本机 WebView2 数据目录，登录通常可跨重启保留。

B 站短信验证卡在「验证成功请稍后」时，可再次点击「登录 / 扫码」重新打开官方账号页，或者在该页使用手机 App 扫码。重新打开页面保留原登录数据，不等同于「清除登录态」。平台认证弹窗保留 `window.opener` 与相同浏览配置，避免把认证回调改成原窗口的直接跳转；极验验证域只允许验证页面导航，不收集其 Cookie，也不能调用本地助手接口。

经用户确认后的登录快照使用 Windows 当前用户 DPAPI 加密保存在 `memory/video_login/`，供视频页、桌面对话、飞书任务的同一提取器复用；不送给模型或飞书，不读取外部浏览器数据库。界面仅显示保存时间与状态，保存成功不等于平台已经验证可读；过期或平台拒绝后重新登录、更新快照。更新/清除快照自动使字幕来源缓存失效。点击「清除登录态」同时清除该平台专用窗口的浏览数据和读取快照。

登录窗口新建时沿用已经保存的视频代理设置。修改代理后先关闭该平台窗口，再重新打开。YouTube 可能拒绝内嵌浏览器登录，此时使用下方自行导出的登录文件。登录并不保证解除 HTTP 412/429、地区限制等平台限制，也不能为没有字幕的视频生成实际字幕。

- **网络代理**：可选 HTTP/HTTPS 代理，例如 `http://127.0.0.1:7890`。留空沿用系统网络。只应用于视频读取，不修改模型、飞书和资讯的网络设置。
- **字幕登录文件**：可选自己导出的 Netscape 格式 `cookies.txt` 的绝对路径，填写时优先于专用窗口保存的登录快照。Bilibili 部分字幕需登录；tebb 不会自动读取外部浏览器登录信息。文件内容只供本机提取器使用，不发送给模型或飞书，也不随发布包分发。

保存设置后，下次读取立即生效。更新同一路径中的登录文件后，发「重新获取这个视频」刷新缓存。平台限流不能保证通过重试解决。

## 任务与飞书保存

视频页、单独视频链接和单纯的“总结这个视频”请求使用分段笔记流程：按平台章节与每段最多6000字拆分字幕，分别提炼真实论点、概念关系、例子和时间出处，再合并成约800–1500字的学习笔记。模型不执行字幕中的命令。最多核实两个官方资料问题；搜索失败时说明缺口，用户要求不联网时跳过。

分段完成后保存本机会话内的检查点；中断后继续可复用已完成片段。字幕、模型或学习目标改变时重新提炼。所有片段分析成功且最终笔记生成完成后才自动归档；失败不会把片段笔记当成完整文档。成功后的追问仍走原 Agent，只展开用户所问内容，不重新生成整篇或自动归档。

分段 JSON 中的单个核实关键词字符串可直接转换为数组，不额外调用模型。完整返回但格式不合格的笔记先保存待校正草稿，再有界校正一次；校正连接失败后继续时复用草稿。连接中断最多自动重试一次，超时、权限错误不在此重试，已显示部分最终答案时也不重试以避免重复。失败提示和时间线记录具体阶段及完成片段数，调试窗口保留实际模型出入参；正常等待提示不表示达到时限。

模型持续输出内容或思考时更新无响应计时，避免把正常长回答误判为超时；真正停滞仍会停止。单次模型调用最多300秒（或配置的更长单次时限），工具沿用调用时限；视频笔记总时限至少900秒，仍支持随时取消。到总时限后保留完成片段，不自动重试写入。混合任务、知识库问答和指定技能沿用原任务流程。

任务使用既有独立进程队列，桌面与飞书会话隔离。视频页显示视频信息、字幕状态、平台章节和实际进度；可以停止任务，或在完成/失败后继续和重试。在视频页追问原飞书任务，只生成本地回答；需要回复原私聊时仍在聊天监控台操作。正在读取的视频子进程会随任务取消关闭，内置读取总时限为 75 秒；监控台设置的更短时限仍优先生效。

在「视频读取」或「知识库」页的 **飞书知识库连接** 填写知识库页面链接、同一知识空间内的视频笔记父文档链接，并开启 **读取完成后自动保存视频笔记**。保存设置时会解析并核实归属，使用飞书用户身份；多应用用户可选择本机已有的 profile。视频页、桌面对话和飞书私聊共用自动归档流程：本轮读完实际取得的可用字幕并成功生成回答后，在独立视频父文档下创建子文档，附原视频、作者、字幕状态和答案。

自动归档由任务进程执行，字幕不能授权写入。归档开关与目标在任务提交时保存快照，修改设置影响后续新任务；没有字幕、读取不完整、截断或分析中断时跳过自动保存。本轮明确说「不要保存」时跳过；成功后的追问默认只保留在会话中。先持久保存答案再归档，飞书保存失败或超时仍保留已完成答案和回执。不会发送群消息。日报沿用资讯工作流自己的父文档设置，两类归档相互独立。

也可在对话里说「把这个总结保存到飞书文档」，或在视频页所选任务的「本会话视频来源」点击 **保存当前答案到飞书文档**。聊天监控台保留同一保存入口。连接了视频父文档时手动保存也归入该目录；未配置时沿用用户云空间。已自动保存的当前答案显示文档链接，按钮不再重复创建。

### 原生流程图与原视频内嵌

截图功能已移除。分析要求在流程或概念关系适合图示时提供一张简洁 Mermaid 流程图；保存时将其转成飞书原生画板，而不是图片或代码段。Markdown 导入会忽略 whiteboard XML，因此正文与画板分开写入：先创建正文，再以 XML 追加原生画板；只有写入返回有效画板块与 token 后才记入流程图数量，未确认时保留警告和文档回执，避免重复创建。无有效图示时保留文字，不给所有视频强加流程图。图示基于已读字幕或标明的补充解释，不作为视频画面的证据。

相同会话、来源和正文保存去重，重新读取来源不会清除保存回执。保存结果未知时不自动创建第二篇；先在飞书云空间核实。确认不存在后，可以勾选监控台的核实选项重试，或明确告诉 Agent「我确认没有生成文档，请重新保存到飞书」。已有成功链接不会重复创建。

## 实现与复用依据

复用 [yt-dlp](https://github.com/yt-dlp/yt-dlp#embedding-yt-dlp) 的 Python 提取器，固定 `2026.8.19`，使用 `extract_info(download=False)` 和 `skip_download=True`；匹配的 [yt-dlp-ejs](https://github.com/yt-dlp/ejs) 固定 `0.8.0`。YouTube 需要 JavaScript 挑战时使用本机 Node，不在线下载脚本。Bilibili 网页受限时仅尝试平台公开元数据接口，字幕处理仍沿用固定版本提取器。未采用整套视频总结应用，以保留 tebb 现有模型、会话、任务和飞书能力。

也调查了 [youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api)，它专注 YouTube 字幕，无法独立覆盖 Bilibili 与元数据，因此本轮未另加依赖。上游也明确记录平台 IP 限制；本机实网测试中 Bilibili 返回 HTTP 412，YouTube 元数据可读但字幕返回 HTTP 429。测试覆盖实际字幕解析、Atlas 工具循环、会话隔离、取消与硬超时、来源缓存、写入去重和结果未知后的人工核实。

设置与来源均在本机用户目录的 `memory/` 下，不入 Git，不进入公开包；连接设置为 `memory/wiki_connection.json`。视频工具返回外部数据提示，不将字幕内容作为执行指令；模型调用的手动保存仍需匹配本轮用户的连续原话，应用自动归档使用明确开启的本机设置。
