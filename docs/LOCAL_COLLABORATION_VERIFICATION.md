## 已通过的真实执行场景

| 场景 | 实际观察 |
| --- | --- |
| 给定材料的研究→写作 | 协调者生成计划，研究员比较三个虚构框架，写作者得到研究成果并输出报告，正确选择满足内存与插件条件的框架丙，包含验收标记。这里验证模型执行与交接，不把虚构材料当作现实项目事实。 |
| 追加要求 | 研究任务收到“指出甲缺插件、乙超内存”的补充，应用版本为1，最终报告保留该约束。调用过程中收到补充、迟到补充不提前交接另有确定性回归覆盖。 |
| 聊天与任务分离 | 首轮长任务进行时，另一条聊天消息独立完成；重复提交相同消息编号只产生一个聊天工作。 |
| 真正停止进程 | 另一条协作链中研究员已经进入模型调用后，停止根协作链，研究任务转为 cancelled，等待中的写作者取消且模型调用次数为0。 |
| 浏览器权限 | 使用实际临时能力凭证连接 `/collaboration` 成功；同一连接调用 `terminal_start` 被拒绝。 |

## Issue #88：正文与引用复测（2026-10-16）

此前 Jev 调研的两次搜索超时，仅能在人工补充资料后写报告。本轮补充了主搜索限时恢复与公共 Bing 备用搜索、独立网页正文权限、结构化证据交接和引用URL核验。不是 Jev 模型本体的性能或 API 测试。

- 第一轮实际发现：研究员读到4篇正文，但引用解析将相邻中文标点与正文拼进URL，误判引用失败，等待中的写作者取消、调用次数为0。保留失败记录，修正解析并补齐中文相邻链接和含括号URL回归，未手工修改任务终态。
- 新建无旧会话内容的群后重跑，没有提供来源URL或人工采集的正文。协调者、研究员、写作者全部成功，合计5次真实模型调用，整条链工作进程的墙钟跨度约289秒。
- 自主搜索2次：一次模型服务主搜索暂不可用，实际经 `bing-rss` 备用渠道恢复；另一次由 `model-api` 返回。渠道和主搜索失败原因留在证据记录中，未将备用渠道标成主服务成功。
- 自主读取4篇TypeSafe官方正文：模型规格、1.14更新、介绍、首次发布；首次发布文章保留12000字符节选，其余3篇未截断。证据含实际URL、UTC采集时间、正文哈希和截断标记。
- 研究员结束后写作者才启动。最终报告6个不同引用链接通过来源匹配：4项正文、2项搜索摘要；摘要未读全文的限制在报告中保留。报告涵盖预览/稳定通道、实验功能、价格、上下文和tebb候选用途，也保留未取得独立评估正文的缺口。

## Issue #95：浮动聊天延迟与后台反馈（2026-10-16）
