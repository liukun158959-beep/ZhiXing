## 修复

- 路由只判断回答或执行，不再用模型改写的执行说明替换原始用户目标；当前请求与历史资料分开呈现。重复的合法后台任务意图合并为一条原始目标，不重复派发。
- 有界计划支持最多 3 项任务：资料采集可并行，综合交付等待全部前序。前序正文与证据随依赖传递，兼容旧单依赖任务；停止任一前序会停止依赖者。
- 原用户目标、阶段、来源要求与模型配置贯穿子任务。私有仓库阅读继续使用已有权限和 GitHub CLI 登录，不扩大目录或命令权限。
- 默认仍为 2 次搜索、4 次读取。多对象采集根据经校验的 `source_topics` 分配额度，最多 4 个对象、4 次搜索和 8 次读取；例如三对象为 3/6。任务总时限保持原设置。
- 未通过来源规则、未发出请求的链接不扣实际读取额度。GitHub 等扩展工具不再误扣搜索额度。XML 伪工具调用只做有限格式纠正，不解析执行。
- 采集任务通常最多 8 次模型调用，编码最多 12 次；只读任务预留最后两次收尾，文件/命令任务保留最后一次，便于完成实际验证。引用修订要求返回完整稿，预算用尽显示具体原因。
- 证据使用由真实 URL 派生的稳定编号，跨伙伴保持一致；客户端交付转换为真实 Markdown 链接。未知编号和未取得的 URL 仍会拒绝，代码示例中的文字不改写。
- 综合交付明确区分核心目标缺失和附加信息缺口；仅有框架不能通过。规划结束显示整条链的进行中/未完成/已交付状态，不能以计划生成成功代替任务完成。
